# Windows 多点配送二维仿真

这是不连接 ROS、底盘或实车的桌面演示。使用纯 Python 标准库，地图每格代表 0.5 米；虚拟车从 H（装载点）出发，到所选配送点 A/B/C/D/E 送货，每站等待人工确认，最后返回 H。可切换“经典障碍”“仓库通道”“空旷地图”三张示例地图。地图中深色格为障碍，可在运行中点击增删；路径被挡时尝试重新规划，无路可走则停止并记录原因。

## 运行

在 Windows 中双击仓库根目录的 `start_delivery_sim.cmd`。也可以在仓库根目录打开 PowerShell：

```powershell
python -m delivery_sim
```

输入 `A,B,C`、`E,D,A` 等不重复的配送点，点击“开始配送”。到站后点击“确认取货”；可以暂停、取消或在地图上点击增删障碍。切换地图会重置当前任务。选择“按输入顺序配送”会严格遵循输入顺序；选择“自动排序”会自行安排这些点。交互演示使用路径记忆算法。“内置场景自动测试 10 次”使用固定示例，不读取输入框或当前地图，包含一个预期失败场景，正常结果是 9/10 成功。

## 两种配送算法对比

配送方式与算法分开选择。配送方式是“自动排序”或“按输入顺序”；对比按钮会在**相同的当前地图、手动障碍、配送点和配送方式**下运行这两种算法：

- **普通多点配送算法**：自动排序时使用常见的最近邻贪心法，每次选择当前最近的未配送点；每段路都重新用广度优先搜索（BFS）寻路。按输入顺序时跳过最近邻选择，直接依次寻路。
- **路径记忆算法（简化版）**：缓存已算过的站点间网格路径，复用前检查障碍；自动排序时枚举所选站点的顺序，选择总网格路程最短的路线。按输入顺序时保留输入顺序，只复用路径。

“当前条件对比 1 次”分别运行两种算法一次。“当前条件对比 10 次”在同一静态地图和同一订单上重复十次，普通算法每次重新寻路，路径记忆可跨次复用缓存。这十次是重复试验，不是十张不同地图。弹窗分别显示实际访问顺序、合计路程、寻路次数和记忆命中次数；每次轨迹保存在 `artifacts/delivery_sim/comparison_*.json`。按输入顺序时两种算法通常走一样长的路，差别主要在寻路次数；自动排序时路线差异来自最近邻与枚举最短顺序的差别，不能单独归因于路径记忆。这些数字只反映本程序的网格仿真，不代表论文的性能结果。

核心逻辑检查：

```powershell
python -m unittest delivery_sim.test_core
```

## 验证范围

路径记忆模式参考了 [Multi-Goal Motion Memory 论文](https://arxiv.org/abs/2407.11399)中“复用历史路径、估算目标点间代价、优化访问顺序”的思路，**没有使用或复制[作者 C++ 源码](https://github.com/yuanjielu-64/MGMM_ICRA2025)**。这里没有论文的学习模型、运动地图采样或车辆动力学约束，不能称为 MGMM 原算法复现。

本程序验证订单顺序、到站停等、人工确认、网格寻路、改道和停止等任务流程。地图是示意图，位置、激光、里程计和运动均为软件模型；它**没有调用 Nav2，也不能证明真实小车的定位、避障或制动性能**。接入 ROS 2 时，需要用 Nav2 导航反馈替换网格移动，并单独设计配送模式的运动授权，不得直接绕过 `motion_guard`。
