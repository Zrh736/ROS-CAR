# Windows 多点配送二维仿真

这是不连接 ROS、底盘或实车的桌面演示。使用纯 Python 标准库，地图每格代表 0.5 米；虚拟车从 H（装载点）出发，到所选配送点 A/B/C/D/E 送货，每站等待人工确认，最后返回 H。可切换“经典障碍”“仓库通道”“空旷地图”三张示例地图。地图中深色格为障碍，可在运行中点击增删；路径被挡时尝试重新规划，无路可走则停止并记录原因。

## 运行

在 Windows 中双击仓库根目录的 `start_delivery_sim.cmd`。也可以在仓库根目录打开 PowerShell：

```powershell
python -m delivery_sim
```

输入 `A,B,C`、`E,D,A` 等不重复的配送点，点击“开始配送”。到站后点击“确认取货”；可以暂停、取消或在地图上点击增删障碍。切换地图会重置当前任务。选择“按输入顺序配送”才会严格遵循输入顺序；“路径记忆 + 自动排序”会自行安排这些点。“内置场景自动测试 10 次”使用固定示例，不读取输入框或当前地图，包含一个预期失败场景，正常结果是 9/10 成功。

## 路径记忆与对照

界面有两种模式：

- **路径记忆 + 自动排序**：把输入视为要访问的站点集合，复用已计算的站点间网格路径；复用前检查路径是否被新障碍挡住，若挡住则重新寻路。根据目标点间的实际网格路程，枚举所选配送点的访问顺序，并在每站确认后重新计算剩余顺序。
- **按输入顺序配送**：把输入视为必须遵守的顺序，每段都重新寻路，用作对照。

点击“当前订单对比”，程序会在**当前地图**上用输入框中的同一组配送点各运行一次，弹窗分别显示实际访问顺序、路程、寻路次数和记忆命中次数，详细结果保存在 `artifacts/delivery_sim/current_comparison_*.json`。改变输入顺序会改变“按输入顺序配送”的路线；如果所选配送点相同，自动排序仍可能给出相同的最短路线。“内置样例对比 10 次”使用经典障碍地图和预设的 A/B/C 顺序，不读取输入框，结果保存在 `comparison_*.json`。这些对照只反映本程序的网格地图，不代表论文的性能结果。路程差异包含自动排序的影响，不能单独归因于路径记忆。

核心逻辑检查：

```powershell
python -m unittest delivery_sim.test_core
```

## 验证范围

路径记忆模式参考了 [Multi-Goal Motion Memory 论文](https://arxiv.org/abs/2407.11399)中“复用历史路径、估算目标点间代价、优化访问顺序”的思路，**没有使用或复制[作者 C++ 源码](https://github.com/yuanjielu-64/MGMM_ICRA2025)**。这里没有论文的学习模型、运动地图采样或车辆动力学约束，不能称为 MGMM 原算法复现。

本程序验证订单顺序、到站停等、人工确认、网格寻路、改道和停止等任务流程。地图是示意图，位置、激光、里程计和运动均为软件模型；它**没有调用 Nav2，也不能证明真实小车的定位、避障或制动性能**。接入 ROS 2 时，需要用 Nav2 导航反馈替换网格移动，并单独设计配送模式的运动授权，不得直接绕过 `motion_guard`。
